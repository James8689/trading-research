# Network and authority

## Model tiers

**Director / frontier:** replaceable strongest appropriate model. It synthesizes disputes, selects at most two active experiments, freezes designs, reviews evidence and approves research gate changes. It sees concise evidence packets, not every worker transcript. A new director can assume responsibility using repository state alone.

**Specialist / standard:** optional middle tier for ambiguous source interpretation, code review, accounting or statistical design. Escalate a bounded task here when a cheap model cannot solve it reliably. Do not place this tier on every task by default.

**Worker / economy:** extraction, source inventory, schema validation suggestions, duplicate screening and narrow falsification. Cheap is an empirical cost/quality designation, not a claim about an agent's intrinsic intelligence. Configuration currently names example models only; actual access, billing and quality must be measured.

**Deterministic controller:** no model for hashes, schedules, manifests, arithmetic, format validation or state transitions. The future controller checks prerequisites; it does not infer scientific success from free text.

## Roles and deliverables

- Scout: proposed mechanism with all eight requested dimensions and prior-art/deduplication notes. No new return data.
- Mechanism investigator: original clauses, exceptions, participant incentives and claims-to-source map. Separate observed facts from inferred price response.
- Data auditor: exact historical field availability, original timestamps, universe completeness, missing-case denominator and acquisition cost.
- Extractor (later stage): bounded document-to-event rows with source offsets and hashes. Ambiguous rows flagged, not guessed. Independent reader checks critical fields.
- Experiment architect: frontier or calibrated specialist; exact rule, estimand, controls, cost model, power/event-count constraints and untouched window before new outcomes.
- Offline engineer (later stage): frozen-plan implementation and meaningful accounting/timing tests. No strategy optimization, broker orders or autonomous modification of research rules.
- Falsifier: independent counterexplanation, contamination and execution review. Cannot silently rewrite a hypothesis it attacks.
- Validation custodian (later stage): isolates prospective outcome access and releases only predeclared data-quality summaries until scheduled evaluation. Must not be the rule tuner.
- Replicator (later stage): clean rerun against immutable inputs with cash/share reconciliation and independent timing review.
- Director: explicit advance/reject/blocked/inconclusive decision with artifact references and dissent preserved.

## Delegation contract

One task has one owner, one measurable question, bounded source paths, one artifact directory and an expiry. Workers own their local context/memory, but do not own shared budget or canonical strategy state. Workers may propose child tasks; the controller/director grants IDs and budget before dispatch. Maximum planned delegation depth is two (director -> specialist lead -> leaf); all leaves count against one global concurrency/call budget. Initial design uses direct leaves only.

Default concurrency target: three leaf workers plus director. Logical role count can be larger; idle role prompts cost nothing. Mechanism/data tasks may run together after an idea is registered. Falsifier receives source facts and the hypothesis before the director's recommendation, reducing anchoring. It then sees the recommendation in a separate conflict-resolution pass if needed. Different model families are optional; distinct evidence and blind work matter more than agent count.

The same task author cannot provide its sole validation. Two agreeing cheap agents are not proof. A frontier director verifies every critical gate claim from original evidence or an independently tested calculation. Minor formatting does not require frontier review.

## File authority

Workers write only `runs/<run-id>/tasks/<task-id>/` in the eventual implementation. Shared raw data, frozen plans and the rejection ledger are immutable to workers. Only a validated controller transaction updates canonical records. Engineering work goes in an isolated branch/worktree with one owner; merging code is a separate reviewed action. Context files do not carry secrets or authority from web pages.

No role has live-order permission. Quote-observation capability is separate from trading credentials. Automatic promotion ends at "implementation consideration", never at "start trading".
