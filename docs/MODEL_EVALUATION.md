# Model evaluation for research judgment

This fixture evaluates whether a worker can falsify trading research claims before a coordinator relies on them. Each worker receives only one task's `prompt`. The evaluator retains `fixture.hidden_expected_disposition` and `fixture.hidden_expected_reason`; those fields are never shown to the worker. The set contains eight known failure modes and two mechanisms that are plausible but unproven. A good worker must reject unsupported claims for the former and request evidence for the latter, rather than rejecting every idea or accepting every backtest.

The comparison unit is one fresh worker run per task. Use the same prompt, task order policy, and output contract for every model tier. The coordinator should ask for a disposition (`reject`, `accept`, or `hold_for_evidence`), the specific evidence that supports it, and the smallest rework needed. A response is correct only when its disposition and substantive reason match the hidden fixture. A critical miss is accepting a known-invalid result, calling a plausible unproven mechanism false, or missing the central validity failure. Rework is counted when the disposition is directionally right but the worker omits a required repair or asks for evidence that would not resolve the stated issue.

Compare models on correctness rate, critical misses, and rework required. Also record actual measured input tokens, output tokens, wall time, and billed cost from the run metadata. Do not fabricate prices, token counts, or savings from a model's list price. The economics are not guaranteed: a cheap worker may need more retries or coordinator repair, and a more expensive tier may reduce rework. Report both per-task and aggregate measurements, with the fixture version and run date.

The project has not benchmarked cheap workers yet. Model names and worker tiers are configuration values that can be swapped without changing the fixture; configured tiers are interchangeable labels, not a claim that any tier has a particular accuracy, latency, or price. No conclusion about cost effectiveness should be made until measured runs exist.

For each task, use a fresh worker context with no prior task outputs, hidden labels, or aggregate score. The frontier coordinator should blind-review the worker response against the hidden fixture, then request a second independent review when the first disposition is `accept`, `hold_for_evidence`, or otherwise uncertain. The second reviewer receives the original prompt and first response only as needed to check the reasoning, not the hidden answer. The coordinator resolves disagreements by citing the task evidence and preserving both rationales in the run record. Independent fresh contexts reduce contamination from earlier answers and make correlated hallucinations visible; agreement between two workers is evidence about reproducibility, not proof of a market edge.

The evaluator should keep research validity separate from strategy performance. A passing judgment only says that the worker identified the fixture's methodological issue. It does not validate a return, causal mechanism, live trade, or deployment decision. Any surviving claim still needs frozen rules, point-in-time data, realistic spreads/slippage/latency, concentration analysis, and an untouched validation period under the repository's deployment gate.
